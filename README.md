- **فاز ۲۸** ✅: چت — ویجت شناور + پیوست فایل + استیکر (بدون Migration) — دکمهٔ شناور چت (`ChatWidget`) در `AppShell` روی همهٔ صفحات به‌جز خود `/chat` دیده می‌شه (نشان تعداد پیام نخوانده، پنل کشویی با لیست مکالمه‌ها → مینی‌گفتگو، لینک «باز کردن در حالت کامل»)، دقیقاً از همون Hook های صفحهٔ کامل چت (`useConversations`/`useMessages`/`useChatMutations`) استفاده می‌کنه بدون state جدا؛ `MessageBubble`/`MessageComposer`/`Avatar`/`conversationName` به کامپوننت‌های مشترک استخراج شدن تا صفحهٔ کامل و ویجت تکرار نداشته باشن — پیوست فایل و استیکر هیچ‌کدوم Migration نخواستن: ستون `chat_messages.file_url` از قبل در اسکیما وجود داشت ولی هیچ‌جا استفاده نمی‌شد (فقط سیم‌کشی DTO/سرویس/فرانت اضافه شد، با ولیدیشن «حداقل متن یا فایل» و بازگشت پیش‌فرض «📎 پیوست» وقتی کپشن خالیه)؛ مجموعهٔ ۱۴ استیکر ثابت کاملاً فرانت‌اندیه — ارسال استیکر فقط یک پیام معمولیه که متنش دقیقاً برابر یکی از ۱۴ اموجیه، تشخیص/رندر به‌صورت اموجی بزرگ بدون حباب هم صرفاً فرانت‌انده (`isSticker()`) — [SPEC-PHASE-28.md](./SPEC-PHASE-28.md)
- **فاز ۲۹** ✅: چت — تجربهٔ تلگرام‌مانند (بازخورد کاربر روی فاز ۲۸، بدون Migration) — (۱) ویجت شناور از دکمهٔ گرد که «جابه‌جا» به‌نظر می‌رسید به یک **نوار ثابت پایین صفحه** (مثل فیسبوک مسنجر) تبدیل شد: نوار همیشه آخرین فرزند یک ستون Flex داخل کانتینر `fixed bottom-0` است، پنل گفتگو فقط بالای همون نوار باز/بسته می‌شه بدون تغییر موقعیت خودِ نوار — (۲) اسکرول خودکار به آخرین پیام: هوک مشترک `useAutoScroll` با پیام جدید (اگه کاربر پایین لیست بود) خودکار می‌ره ته صفحه، وگرنه دکمهٔ شناور «پیام‌های جدید ↓» نشون می‌ده تا کسی که تاریخچه رو می‌خونه پرت نشه پایین — (۳) پیکر ایموجی/استیکر بازطراحی شد: ۷ دسته (لبخند/ژست/قلب/حیوان/غذا/فعالیت/نماد) با ~۱۸۰ ایموجی استاندارد یونیکد (بزرگ‌تر و باکیفیت‌تر از ۱۴تای قبلی، همون گلیف‌هایی که کیبورد اندروید/iOS نشون می‌ده — کپی کردن استیکر اختصاصی اپل/گوگل از نظر کپی‌رایت درست نبود)؛ کلیک روی ایموجی حالا داخل کادر متن درج می‌شه نه ارسال فوری، ارسال واقعی فقط با دکمهٔ ارسال؛ تشخیص «پیام-استیکر» (نمایش اموجی بزرگ بدون حباب) هم از تطبیق با لیست ثابت به یک Regex عمومی تغییر کرد (۱ تا ۳ کاراکتر کاملاً ایموجی، با پشتیبانی از دنبالهٔ ZWJ) — پس چه از پیکر خودمون چه مستقیم از کیبورد سیستم‌عامل تایپ بشه یکسان تشخیص داده می‌شه — (۴) پیش‌نمایش درون‌خطی پیوست مثل تلگرام: تصاویر مستقیم به‌صورت تصویر کوچک گردشده داخل حباب نمایش داده می‌شن (نه فقط آیکون چشم/دانلود)، کلیک = بزرگ‌نمایی در همون Lightbox موجود (`FilePreviewModal` از `FileViewer.tsx` جدا export شد)؛ فایل‌های غیرتصویری به‌شکل کارت سند (آیکون + نام فایل) نمایش داده می‌شن — (۵) رسید خواندن (Read Receipt) برای مکالمهٔ دونفره: `chat_participants.last_read_at` (که از فاز ۱۴ در اسکیما بود ولی هیچ‌جا در پاسخ API برنمی‌گشت) حالا در `GET /chat/conversations` روی هر شرکت‌کننده افشا می‌شه؛ فرانت با مقایسهٔ `lastReadAt` طرف مقابل با `createdAt` هر پیام، تیک تک/دوتیک (مثل واتس‌اپ، روی تک‌تک پیام‌ها) + برچسب «خوانده شد HH:MM» فقط زیر آخرین پیام خوانده‌شده (مثل تلگرام) نشون می‌ده — کاملاً مشتق‌شده، بدون فیلد ذخیره‌شدهٔ جدید. فاصلهٔ Polling مکالمات/پیام‌ها هم برای حس زنده‌تر از ۱۵/۵ ثانیه به ۸/۳ ثانیه کم شد — [SPEC-PHASE-29.md](./SPEC-PHASE-29.md)
- **فاز ۳۰** ✅: چت — قابلیت‌های قدرتمند (بازخورد کاربر روی فاز ۲۹، شامل Migration) — (۱) ویرایش/حذف پیام توسط خودِ فرستنده: `chat_messages.edited_at`/`deleted_at` جدید؛ حذف Soft Delete با تومبستون «این پیام حذف شد» (مثل تلگرام، نه پاک‌کردن واقعی رکورد)؛ هاور روی پیام خودم دو آیکون ویرایش/حذف نشون می‌ده، ویرایش به کادر متن درون‌خطی تبدیل می‌شه، حذف از `ConfirmModal` مشترک پروژه استفاده می‌کنه — (۲) ساخت مکالمهٔ جدید از حالت ویجت: `NewGroupModal`/`NewDirectModal` به فایل مشترک استخراج شدن تا `ChatWidget` هم بدون تکرار کد بتونه ازشون استفاده کنه — (۳) Drag & Drop: `MessageComposer` متد `addFiles` رو روی `ref` expose می‌کنه، والد کل ناحیهٔ پیام‌ها رو Drop-Zone می‌کنه با Overlay نیمه‌شفاف حین کشیدن فایل — (۴) کپشن مثل تلگرام: فایل انتخاب‌شده (📎 یا Drag&Drop) بلافاصله ارسال نمی‌شه، اول در نوار پیش‌نمایش (thumbnail/آیکون + دکمهٔ ×) می‌شینه و کادر متن به «افزودن توضیح» تبدیل می‌شه، فقط با دکمهٔ ارسال واقعاً می‌ره؛ **حین همین تست زنده یک باگ واقعی کشف و رفع شد** — تشخیص «تصویره یا نه» قبلاً از پسوند `messageText` بود که با کپشن دلخواه اشتباه می‌شد، حالا از پسوند خودِ `fileUrl` تشخیص داده می‌شه (همیشه درست، فارغ از کپشن) و کپشن هم حالا زیر تصویر قابل‌مشاهده‌ست — (۵) جست‌وجو در پیام‌ها: کاملاً سمت کلاینت (بدون تغییر بک‌اند، چون پیام‌ها از قبل بدون صفحه‌بندی لود می‌شن)، هوک مشترک `use-message-search.ts` با شمارندهٔ N/M + پیمایش + اسکرول‌خودکار+هایلایت، دقیقاً مثل Ctrl+F تلگرام — (۶) استیکر با گرافیک Twemoji محلی به‌جای فونت ایموجی ویندوز (که کیفیت پایینی داره): پکیج متن‌باز `twemoji-svg` (MIT+CC-BY-4.0، همون سبک دیسکورد/اسلک) موقتاً نصب شد، فقط SVGهای ۱۳۴ ایموجی مجموعهٔ فاز ۲۹ کپی و نگاشت `emoji-codepoints.generated.ts` تولید شد، پکیج بعدش حذف شد (فقط برای تولید یک‌بارمصرف Asset لازم بود)؛ کامپوننت جدید `EmojiImage.tsx` هر ایموجی رو تصویر SVG محلی رندر می‌کنه با بازگشت امن به متن معمولی برای ایموجی‌های خارج از مجموعه — Migration `0017_chat_message_edit_delete` — [SPEC-PHASE-30.md](./SPEC-PHASE-30.md)

- **فاز ۳۱** ✅: مرکز اقدامات (Action Center) — طبق تحلیل معماری تأییدشدهٔ [SPEC-PHASE-31.md](./SPEC-PHASE-31.md) (الگوی «صندوق ورودی فدرال»، مثل SAP Fiori My Inbox): به‌جای جدول جدید، `activities` موجود (فاز ۱۶) گسترش پیدا کرد (وضعیت `in_progress` + `waiting_reason`) و یک سرویس تجمیع‌گر تازهٔ Read-Only (`ActionCenterModule`) از منابع پراکندهٔ موجود — فعالیت‌های شخصی، ۵ تأیید HR (مرخصی/مأموریت/اضافه‌کاری/وام/درخواست عمومی)، درخواست اصلاح محموله (فاز ۲۷)، نامه‌های ارجاع‌شده (فاز ۲۴) — یک لیست واحد (`ActionItem[]`) با کارت‌های خلاصه (سررسیدگذشته/امروز/این‌هفته/بعداً)، فیلتر نوع/اولویت و دکمهٔ اقدام سریع (تکمیل/تأیید/رد) می‌سازه؛ هیچ دادهٔ موجودی جابه‌جا نشد — هر منبع همچنان تحت منطق تخصصی خودش می‌مونه. صفحهٔ سراسری جدید «مرکز اقدامات» در سایدبار (اولین آیتم گروه «کار روزمره») با نشان‌گر عددی (سررسیدگذشته+امروز)؛ کلید RBAC جدید `action_center.view_team` (طبق سؤال باز #۲ سند، در کنار گروه هارد-کدشدهٔ «مدیریت»)؛ به‌عنوان اولین نمونهٔ واقعی «Workflow Generated Action»، ارسال RFQ حالا خودکار یک فعالیت پیگیریِ نوع `follow_up` با Deadline واقعی همون RFQ (نه عدد ثابت) برای کارشناس بازرگانی می‌سازه — Migration `0018_action_center` — [SPEC-PHASE-31.md](./SPEC-PHASE-31.md)

## پیش‌نیازها

- Node.js 18.12+ (نسخه دقیق در `.nvmrc`)
- pnpm 8.x — سازگار با Node 18. اگه pnpm نصب نیست: `corepack enable && corepack prepare pnpm@8.15.9 --activate` یا `npm install -g pnpm@8`
  (نسخه‌های جدیدتر pnpm به Node 22+ نیاز دارن و با این پروژه کار نمی‌کنن)
- Docker Desktop (برای Postgres + اجرای کامل API)

## راه‌اندازی

```bash
# ۱. وابستگی‌ها
pnpm install

# ۲. فایل‌های env (برای هر دو app کپی کن و مقادیر واقعی رو جایگزین کن)
cp apps/api/.env.example apps/api/.env
cp apps/web/.env.example apps/web/.env

# ۳. بالا آوردن Postgres (و اختیاری: کل استک با Docker)
docker compose up -d postgres

# ۴. اجرای Migration ها (0000_extensions، 0001_baseline = عیناً erp-schema.sql، 0002_auth_fields)
pnpm --filter api exec prisma migrate deploy

# ۵. Generate کردن Prisma Client
pnpm --filter api exec prisma generate

# ۶. Seed (کاتالوگ کامل ۱۱ ماژول دسترسی + ۴ گروه پیش‌فرض mockup + کاربر ادمین)
pnpm --filter api run seed

# ۷. اجرای هم‌زمان API و Web در حالت dev
pnpm dev
```

- API روی `http://localhost:3000`
- Web روی `http://localhost:5173`
- ورود اولیه با `SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD` از `apps/api/.env` (گروه «مدیریت»)

## ⚠️ محدودیت‌های این محیط توسعه (نیاز به تأیید شما با Docker واقعی)

این پروژه توی محیطی Scaffold شد که **نه Docker نصب بود و نه یک PostgreSQL در دسترس** —
پس بخش‌های زیر نوشته شدن ولی به‌صورت زنده اجرا/تست نشدن:

1. **`apps/api/prisma/schema.prisma` دستی نوشته شده، نه با `prisma db pull`.**
   فقط مدل‌های استفاده‌شده در فاز ۱ (User, Permission, PermissionGroup,
   PermissionGroupItem, RefreshToken) توش هست — نه کل ۹ دامنه‌ی `erp-schema.sql`.
   بعد از اجرای migration ها روی یک دیتابیس واقعی، این دستور رو بزن تا مطمئن بشی
   دقیقاً با ساختار واقعی هم‌خوانه (و مدل‌های فازهای بعد هم اضافه بشن):
   ```bash
   pnpm --filter api exec prisma db pull
   ```
2. **`docker-compose.yml` و `apps/api/Dockerfile`** نوشته شدن ولی `docker compose up`
   یک‌بار هم اجرا نشده — اگه هنگام Build مشکلی دیدی (خصوصاً مسیرهای pnpm workspace
   داخل Dockerfile)، اطلاع بده تا اصلاح کنم.
3. **جریان کامل ثبت‌نام → تأیید مدیر → ورود → refresh → logout** فقط منطقی/از روی کد
   بررسی شده؛ روی دیتابیس واقعی تست نشده. لطفاً بعد از `pnpm dev` این مسیر رو دستی
   امتحان کن:
   - `/register` یک کاربر جدید بساز
   - با ادمین seed وارد شو، از منوی «کاربران و گروه‌های دسترسی» بخش «در انتظار تأیید»،
     کاربر جدید رو تأیید و گروهش رو تعیین کن (از فاز ۲ دیگه نیازی به curl نیست)
   - حالا کاربر تازه‌تأییدشده باید بتونه از `/login` وارد بشه
4. **فاز ۲ (شرکت‌ها/کاتالوگ/کاربران)**: CRUD و هشدار شباهت (pg_trgm) روی دیتابیس واقعی
   تست نشده — خصوصاً `GET /business-partners/similar` و `GET /item-catalog/similar` که
   `similarity()` رو با `$queryRaw` صدا می‌زنن و بدون extension `pg_trgm` خطا می‌دن
   (migration `0000_extensions` نصبش می‌کنه).
